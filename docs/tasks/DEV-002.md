# DEV-002 Capture と Replay 互換性の技術検証

Status: In progress
Owner: implementer
Phase: P1  
Product relation: TRACE-CAP-001, TRACE-CAP-002, TRACE-DECODE-001, REPLAY-EDIT-001

## 目的

DEV-001 の proxy chain を維持したまま、後の検索、編集、意味的 replay に必要な request 情報を保存し、プロセス再起動後に読み戻せることを証明する。完成 UI や本番用 storage は作らず、記録契約と技術経路を確定する。

## 必須コンテキスト

- `/AGENTS.md`
- `/docs/development/WORKFLOW.md`
- `/docs/architecture/CAPTURE_CONTRACT.md`
- `/docs/reviews/DEV-001-review-001.md`
- この文書

過去の会話は不要である。

## スコープ

含む:

- inspector から request record を生成する capture addon または同等機構
- runtime record を Git 管理外へ保存
- capture schema version
- raw path/query、ordered headers、raw body bytes、body metadata、capture status
- 保存後の inspector/reader 再起動と読み戻し
- 保存済み request の意味的 replay
- query または form の一項目を変更した replay
- JSON、URL-encoded form、multipart、binary body の検証
- 重複 query と重複可能 header の保持検証
- 大容量 upload の転送継続と capture limit 状態
- WebSocket handshake の pass-through と metadata 記録
- 自動 black-box test と検証文書

含まない:

- 管理 UI
- 長期運用 DB の確定
- 20 GB retention cleanup
- Docker discovery
- 自動 request rewrite rule
- live intercept
- response body の完全保存
- 認証、権限分離、機密情報 filter、公開環境 hardening

## 記録の最低条件

記録は `/docs/architecture/CAPTURE_CONTRACT.md` に従う。特に次を禁止する。

- query/header を単一値 map に潰す
- binary body を UTF-8 text のみに変換する
- decoded path だけを保存する
- truncated/metadata-only record を replayable と扱う

## 受入条件

1. DEV-001 の全 routing test が引き続き成功する。
2. GET、JSON POST、URL-encoded form、multipart、binary body の record が保存される。
3. `tag=first&tag=second` のような重複 query が順序付きで保持される。
4. raw body bytes の size と SHA-256 が送信内容と一致する。
5. inspector または reader の再起動後に既存 record を読み戻せる。
6. 完全 record 一件を replay し、Echo target で method/path/query/body の意味的一致を確認できる。
7. 保存済み record の query または URL-encoded form 一項目を変更して replay し、変更後の値だけが target に届く。
8. 100 MiB upload が target まで完了し、capture 上限を超えた場合は `truncated` または `metadata-only` として non-replayable になる。メモリ量の厳密 benchmark は本 task の範囲外とする。
9. WebSocket 接続を破壊せず、handshake metadata を記録する。frame 保存/replay は不要。
10. capture parse failure が proxy routing を停止させない。
11. 一つの自動 test command で上記を再現できる。

## 失敗時の扱い

- mitmproxy native flow だけでは contract を安定して出力できない場合、addon で project-owned record を生成する。
- body capture が大容量転送を壊す場合、capture limit を導入し、上限超過を non-replayable として明示する。
- 二つの記録方法を試しても小さな request の raw bytes、重複値、再起動後読み戻しを同時に満たせない場合は `Blocked` とする。
- security hardening を理由に task を停止しない。
