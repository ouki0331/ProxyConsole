## 目的

手動編集なしで domain route を作成、複製、変更、有効化・無効化し、検証済み Nginx 設定へ原子的に反映できる control plane core を実装する。Docker discovery と Web UI は後続 task に分離する。

## 機能ルール

1. 一つの有効 domain は一つの route だけに属する。
2. 複数 route/domain は同じ upstream host/port を参照できる。
3. 無効 route は設定として保持するが、Nginx へ有効 route として反映しない。
4. copy は新しい route ID を作成し、domain は明示的に変更されるまで conflict 状態として保存せず、作成時に新 domain を必須とする。
5. create/update/delete/enable/disable は desired state 保存と apply result を区別する。
6. 新設定の `nginx -t` が失敗した場合、現在稼働中の設定を変更しない。
7. reload failure 後も旧 route が継続して応答する。

## 受入条件

1. DEV-001〜DEV-011 の全 test が引き続き成功する。
2. API/CLI で手動 upstream route を create/list/get/update/delete できる。
3. route を copy し、新 domain だけ変更して同一 upstream へ転送できる。
4. 異なる複数 domain が同じ upstream へ正しく転送される。
5. enable/disable が live routing に反映され、disabled domain は unknown route になる。
6. duplicate domain、無効 scheme、無効 port、空 host を拒否する。
7. create/update/delete 後、Nginx config が生成され `nginx -t` 成功後に reload される。
8. 故意に不正な生成候補を与えた場合、apply は失敗し、既存 route の応答が継続する。
9. control service/container restart 後も route desired state と最後の apply status が保持される。
10. route config file の一部書き込み状態が Nginx から観測されない。
11. route 変更が inspector/capture/index/retention chain を迂回しない。
12. 一つの自動 test command で全ルールを再現できる。

## 実装上の既定

- 現在の固定 app-a/app-b route は migration/seed として扱い、動的管理へ移行しても DEV-001 regression を維持する。
- Nginx config apply は temporary candidate、validation、atomic replace、reload の順に行う。
- UI 固有の都合を core model/API に混ぜない。
- route apply が失敗しても capture/search/retention API を停止しない。

## 失敗時の扱い

- 一件の不正 route により既存 route が停止する場合は `Blocked` とし、P3 を進めない。
- rollback/旧設定維持を証明できない場合は `Ready for review` にしない。
- security hardening を理由に task を停止しない。

### 実装要約

- **Route 永続モデルと Migration (`migrations/003_routes.sql`, `services/recorder/index_store.py`)**:
  - `routes` テーブル（`route_id`, `domain` UNIQUE, `upstream_scheme`, `upstream_host`, `upstream_port`, `enabled`, `copied_from_route_id`, `description`, `created_at`, `updated_at`）、`route_apply_state` テーブル（`desired_generation`, `applied_generation`, `last_apply_status`, `last_error`, `rolled_back`, `active_config_sha256` 等）、および `route_apply_runs` 履歴テーブルを追加した。
  - 初回初期化時に `route:app-a` (`app-a.local.test -> http://echo-a:8080`) と `route:app-b` (`app-b.local.test -> http://echo-b:8080`) を seed として自動登録し、`DEV-001`〜`DEV-011` の後方互換性を維持した。
- **Route 管理 Core・バリデーション・Nginx 設定生成 (`services/recorder/route_manager.py`, `services/recorder/addon.py`)**:
  - `list` / `get` / `create` / `update` / `delete` / `copy` / `enable` / `disable` / `apply` / `status` を実装した。
  - `domain` の形式検証と重複拒否、`upstream_scheme` (`http` / `https`)、`upstream_host`（空文字・不正形式拒否）、`upstream_port` (`1..65535`)、および `copy` 時の新 `domain` 必須化と重複拒否（Rule 4）を実装した。
  - 複数 domain が同一 upstream を共有する構成に対応し、無効 (`enabled=false`) route は SQLite 上に保持しつつ Nginx 設定からは除外して `404 unknown_host` とした。
  - `addon.py` の `_resolve_route_id` を動的な `routes` テーブル参照と連携させ、動的追加・複製された route のトラフィックも `inspector` -> `capture` -> `index` -> `retention` チェーンを通過して正しい `route_id` で記録されるようにした。
- **原子的 Nginx 反映・`nginx -t` 検証・Rollback (`deploy/nginx/router/router-entrypoint.sh`, `deploy/nginx/router/Dockerfile`, `deploy/nginx/router/default.conf`, `deploy/compose/docker-compose.yml`)**:
  - `router` コンテナ内で (1) 一時ディレクトリ `/tmp/nginx-val-<id>` での分離 `nginx -t` 事前検証（失敗時は稼働中 `/etc/nginx/conf.d/default.conf` を一切変更しない）、(2) `.conf` にマッチしない一時ファイル `/etc/nginx/conf.d/.default.conf.tmp.<id>` からの POSIX 原子的置換 (`mv -f`)、(3) `nginx -s reload` 実行と失敗時の `previous.conf` からの原子的 rollback を実装した。
  - `router` の各 `server` ブロックに `keepalive_timeout 0;` を設定し、`nginx -s reload` 直後に古い worker の idle keep-alive 接続が再利用されないようにした。
- **HTTP API / CLI / 自動統合テスト (`services/recorder/api_server.py`, `services/recorder/capture_cli.py`, `tests/integration/test_route_management.sh`, `Makefile`)**:
  - Control API (`/api/v1/routes`, `/api/v1/routes/status`, `/api/v1/routes/apply`, `/api/v1/routes/<id>`, `/copy`, `/enable`, `/disable`) と CLI (`route-list`, `route-get`, `route-status`, `route-create`, `route-update`, `route-copy`, `route-enable`, `route-disable`, `route-delete`, `route-apply`) を追加した。

### 発見事項

- `nginx -s reload` 直後に `inspector` (`mitmdump`) が reload 前の古い Nginx worker との HTTP/1.1 keep-alive 接続を再利用すると、短時間だけ旧設定で応答する可能性があるため、内部 router の `server` ブロックで `keepalive_timeout 0;` を指定して reload 直後のリクエストが常に新しい worker で処理されるようにした。
- `/etc/nginx/nginx.conf` は `/etc/nginx/conf.d/*.conf` を wildcard include するため、一時ファイル名を `.default.conf.tmp.<id>`（末尾が `.conf` ではない名前）として作成後に `mv -f` で `/etc/nginx/conf.d/default.conf` へ原子的置換することで、一部書き込み状態や一時ファイル重複 include が Nginx から一切観測されないようにした。
