# DEV-041 Web automatic modification rule management console

Status: In progress
Owner: implementer
Phase: P5
Product relation: RULE-MATCH-001, RULE-ACTION-001, RULE-AUDIT-001

## 目的

localhost Web console から DEV-040 の automatic request modification rule を一覧、作成、編集、複製、有効化・無効化、削除、preview でき、CLI や JSON の手編集なしで将来 request の自動変更を管理できるユーザー可視フローを実装する。

## スコープ

含む:

- 既存 Web console への Rules workspace / navigation
- rule list、empty/loading/error state
- create/edit/copy/delete、enable/disable、priority 管理
- route/domain、method、path exact/prefix/regex、query/header pair、content-type match editor
- query/header/cookie、JSON path、URL-encoded form action editor
- human-readable decoded input と action 順序の編集
- inline request または保存済み capture を使う preview/dry-run UI
- matched/applied/skipped/failed rule、before/after、change summary の表示
- validation/runtime error の入力保持と再試行
- browser-level E2E と既存 console regression

含まない:

- rule engine / API business logic の別実装
- response modification
- live interception / manual pause
- multipart file rewrite、WebSocket frame rewrite
- notification aggregation / WebSocket event feed / browser notification（DEV-042）
- authentication、permission、secret filtering、public deployment hardening（P6）

## 機能ルール

1. Web UI は DEV-040 API を使用し、rule evaluation business logic を JavaScript に複製しない。
2. query/header/form は ordered pair と duplicate semantics を失わない編集 UI とする。
3. match と action は追加・削除・並べ替え可能な構造化 row とし、保存 payload を利用者が確認できる。
4. delete と destructive reset は確認を要求し、cancel で state を変更しない。
5. preview は target 送信や capture 増加を起こさず、結果が保存操作と誤認されない表示にする。
6. protected header、unsupported body、streamed/WebSocket skip、runtime failure を成功表示にしない。
7. API error 後も入力を保持し、修正して再送できる。
8. rules workspace の障害で Routes / Docker / Requests / Replay workspace を使用不能にしない。
9. localhost local-first とし、login UI は追加しない。

## 受入条件

1. DEV-001〜DEV-040 の全 test が引き続き成功する。
2. Web console の navigation から Rules workspace を開き、既存 rule の enabled、priority、name/ID、match/action summary を一覧できる。
3. 構造化 form で rule を作成・編集し、route/domain/method/path/query/header/content-type match と query/header/cookie/JSON/form action を保存できる。
4. duplicate pair、Unicode、space、reserved character、action 順序が保存・再読込後も保持される。
5. rule copy は新しい rule ID/name を要求し、元 rule を変更せず複製する。
6. enable/disable、priority 変更、delete が次 request から反映され、browser reload と control-api/inspector restart 後も保持される。
7. invalid regex、schema、action、duplicate rule ID の API error を対象 field 付近に表示し、入力を失わず再試行できる。
8. delete confirmation の cancel/confirm、unsaved edit の cancel が期待通り動作する。
9. inline request preview と保存済み capture preview の双方で、matched/applied/skipped/failed、before/after、change summary を表示し、target request と capture 件数を増やさない。
10. protected header、streamed request、WebSocket handshake、unsupported body type の preview outcome を `skipped` / `failed` と理由付きで表示する。
11. capture detail に存在する rule evaluation metadata を読みやすく表示し、rule ID で Rules workspace または request list filter へ移動できる。
12. Rules API unavailable または validation/runtime failure 時も Routes / Docker / Requests / Replay workspace は継続利用できる。
13. keyboard 操作、focus、label、status/error の live region、狭い画面での主要操作を browser-level test で確認できる。
14. 一つの自動 browser E2E command で list/create/edit/copy/enable/disable/priority/delete/preview/error/restart persistence と既存 console regression を再現できる。

## 失敗時の扱い

- UI 表示だけの問題で API/core が正常な場合は修正して再検証する。
- rule payload の欠落・順序破壊、preview による実送信、誤った成功表示、既存 workspace 停止は blocking とする。
- security hardening、認証、機密情報 filter を理由に task を停止しない。
