## 機能ルール

1. inventoryはEngineの全containerを読み取り、route選択対象だけにfilterしない。
2. containerは`system`、`same_project`、`external_project`、`standalone`に分類し、provider/project/service/nameを原文表示する。
3. healthがないcontainerをunhealthyと誤表示しない。running/stopped、healthy/unhealthy/starting/noneを分離する。
4. route targetの到達可能性は少なくとも`shared_router_network`、`published_host_port`、`network_attachment_required`、`stopped`、`no_tcp_port`を理由付きで返す。
5. external containerを検出しただけでnetwork、label、port、lifecycleを変更しない。
6. published host portを使用する場合はproviderに適したhost aliasをbackendが決定し、利用不能なら選択不可にする。
7. project/service名衝突に耐えるstable inventory IDをcontainer IDベースで持つ。既存`docker:*` target IDは後方互換のため維持する。
8. demo `echo-a` / `echo-b`はtest/example profileへ分離し、通常起動で自動起動しない。integration testは明示profileで起動する。
9. Runtime Projects workspaceはproject grouping、検索、state filter、refresh、provider/status、container/port/reachabilityを表示する。
10. quick routeはcontainer/port行から開き、選択済みcontainerとportを固定表示して、利用者の必須入力をdomainだけにする。
11. route IDは自動生成、schemeは検出値またはhttp、enabledはtrueを既定とする。
12. manual host/port、route ID、scheme、description、disabled creationは`詳細設定`内へ置く。
13. 保存前に`domain → upstream` preview、保存後にapply/疎通結果と既存rollback情報を表示する。
14. stopped/unreachable targetはdisabled actionと理由を表示し、既存routeを自動削除・無効化しない。
15. `Alt+6`はform/dialog/contenteditable編集中に発火させず、reload persistenceと390px layoutを満たす。

## API方針

- 既存 `/api/v1/discovery/*` とroute APIの互換性を維持する。
- host-wide inventoryは新しいread-only endpoint（例: `/api/v1/runtime/projects`）または明示`scope=all` endpointで提供する。
- UI用responseはprovider、projects、containers、summary、refreshed_at、partial errorを返し、一containerのinspect失敗で全一覧を停止しない。
- quick route作成は既存atomic route applyを使用し、新しいnetwork mutation APIは追加しない。

## 実装Agent記入欄

### 実装要約

1. `GET /api/v1/runtime/projects` を追加し、Docker / Podman Engineの全containerをprovider、project、service、state、health、network、port単位でread-only集約した。
2. `system`、`same_project`、`external_project`、`standalone`分類とcontainer IDベースのstable inventory IDを追加した。同名serviceの外部target IDは`engine:<provider>:<short-id>:<port>`として衝突を避けた。
3. shared router network、published host port、loopback-only、network attachment required、stoppedを理由付きで分離した。外部projectは変更せず、到達可能targetだけquick routeで選択できる。
4. Engine inspectの一件失敗を`partial_errors`へ隔離し、host-wide inventory全体を停止させないようにした。
5. `/api/v1/routes/from-target`とroute updateへ後方互換の`target_scope`を追加し、quick routeだけ`all`を明示するようにした。
6. Runtime Projects workspace、Alt+6、project grouping、検索、state filter、provider/summary、DB-like container summary、390px対応を追加した。Overviewのcontainer cardはRuntime Projectsへ遷移する。
7. 到達可能portの`Create Route`からdomainだけで保存・atomic applyするquick flowを追加した。route ID、scheme、description、enabled、manual host/portは`Advanced settings`へ格納した。
8. `echo-a` / `echo-b`を`demo` / `test` Compose profileへ分離し、通常起動ではdemo routeをseedしないようにした。integration testは`test-runtime.sh`からprofileとdemo seedを明示する。
9. Overview E2Eへhost-wide API contract、Alt+6、Japanese navigation、domain-only quick route作成/cleanup、Overview deep linkを追加した。

### 発見事項

- 外部projectのservice名は重複し得るため、従来の`docker:<service>:<port>`をそのままhost-wideに拡張できない。既存same-project IDを維持し、external/standaloneだけcontainer IDベースの新IDを使用した。

- 既存integrationはdemo routeを前提とするため、通常起動からdemoを除外しつつtest profileで明示復元する必要があった。
