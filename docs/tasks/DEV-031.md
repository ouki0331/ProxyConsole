# DEV-031 Web request viewer / editor / replay console

Status: Done
Owner: none
Phase: P4
Product relation: CAPTURE-LIST-001, CAPTURE-DETAIL-001, REPLAY-EDIT-001, REPLAY-SEND-001, REPLAY-EXPORT-001

## 目的

localhost Web console で保存済み request を検索・閲覧し、replayable record から draft を作成して query、headers、cookies、JSON、URL-encoded form を編集し、副作用 warning を確認して replay、cURL/fetch export まで完結できるユーザー可視フローを実装する。

## スコープ

含む:

- Web console の Requests 一覧/検索/ページング
- request detail（method、URL、status、route、timestamps、capture status）
- ordered/duplicate headers と query の表示
- body metadata、human-readable derived view、raw/text fallback
- replayable/non-replayable 状態と理由表示
- record から draft 作成、draft 再読込、削除
- method/scheme/authority/path editor
- ordered pair editor for query/headers
- Cookie key/value editor
- nested JSON editor または検証付き JSON text editor
- duplicate key を保持する URL-encoded form editor
- percent-decoded human-readable input と wire preview
- unsafe method の replay 前 confirmation
- replay 実行、result/status/error、生成 capture と lineage への navigation
- cURL/fetch preview と clipboard copy
- loading、empty、expired draft、validation、API/replay/export error state
- browser-level E2E と live target verification

含まない:

- multipart file の任意編集
- WebSocket frame replay/edit
- gRPC message replay/edit
- live interception / request pause
- automatic request modification rule（P5）
- authentication、permission、secret masking、public deployment hardening（P6）

## UX / 機能ルール

1. Requests 一覧は newest-first を既定とし、既存 DEV-010 filter/page contract を利用する。
2. detail は raw capture を browser で独自解析せず、DEV-010 detail と DEV-030 editor contract を利用する。
3. duplicate query/header の順序を UI 操作で確認・変更でき、map に潰さない。
4. human-readable decoded value と送信 wire preview を区別する。
5. draft edit は元 capture を変更しないことを画面上でも識別できる。
6. non-replayable record は replay action を無効化し、理由を表示する。
7. POST/PUT/PATCH/DELETE replay は method、URL、side-effect warning を明示した confirmation 後だけ送信する。
8. replay/export は保存済み draft の最新 server state を利用し、未保存の古い/新しい値を混在させない。
9. replay 成功後は新 capture ID と元 capture/draft lineage を表示する。
10. clipboard API が利用不能でも cURL/fetch text を選択可能にする。

## 受入条件

1. DEV-001〜DEV-030 の全 test が引き続き成功する。
2. browser で request 一覧、filter、pagination、detail を利用できる。
3. duplicate query/header の順序と値を detail/editor で保持する。
4. percent-encoded Unicode、space、reserved character を人間可読に編集し、wire preview と replay target の意味が一致する。
5. nested JSON、duplicate form key、Cookie の追加・変更・削除を UI から行い、target が期待値を受信する。
6. draft 保存・再読込後も内容が一致し、元 capture detail は不変である。
7. unsafe method は confirmation なしに送信されず、確認後の replay は指定 target へ到達する。
8. replay 後の新 capture が一覧/詳細に現れ、lineage を辿れる。
9. truncated/metadata-only/capture-failed/missing blob record は理由付きで replay disabled となり、target に到達しない。
10. cURL/fetch preview が現在の draft を反映し、copy または選択可能 text として利用できる。
11. expired/deleted draft、validation error、target failure、export error が成功表示にならず、回復操作を示す。
12. page reload/container restart 後の draft persistence が DEV-030 contract と一致する。
13. browser-level E2E で list/detail/draft/edit/replay/export/failure cases を再現できる。
14. UI replay traffic と export 再現 traffic が capture/index/retention chain を通過する。

## 実装上の既定

- 既存 `web/console` の navigation と visual language を拡張し、別 console を作らない。
- DEV-010/DEV-030 API contract を再利用し、browser 内に capture parser/replay engine/exporter を複製しない。
- JSON editor は依存を増やさず検証可能な textarea でもよい。構造化 nested edit の受入結果を満たすことを優先する。
- clipboard は progressive enhancement とし、HTTPS/permission を blocker にしない。
- security hardening を理由に task を停止しない。

## G4 判定

DEV-031 の独立 review で受入条件 1〜14 が合格した場合、DEV-030〜DEV-031 を合わせて G4 passed とする。元 capture の変更、duplicate pair の損失、non-replayable record の誤送信、unsafe method の無確認送信が一件でもある場合は G4 を通過させない。

## 実装 Agent 記入欄

### 実装要約

1. **既存 Web Console への Requests / Detail / Draft Editor / Replay / Export ワークスペース統合（`web/console/index.html`, `web/console/styles.css`, `web/console/app.js`）**
   - 既存 `http://127.0.0.1:18480/` の Web Console にワークスペース切替ナビゲーション（`<nav aria-label="Console Workspaces">`: `All Workspaces` / `Routes & Targets` / `Requests & Replay`）を追加し、既存の Route 管理・Docker discovery 機能を一切損なわずに同一コンソールへ統合した。
   - **Requests 一覧・検索・ページング（Rule 1, AC-2）**:
     - `<search>` ランドマーク内に `method`、`host`、`path_prefix`、`path`、`response_status`、`capture_status`、`source_capture_id`、`draft_id`、`limit`（5/10/20/50）、`sort`（既定 `desc` newest-first）を備えたフィルタとページネーション（Prev / Next / 件数表示）、および保存済み Draft 一覧・ID 指定読込バー（`#saved-drafts-bar`）を実装した。
   - **Request Detail ビュー（Rule 2, Rule 3, Rule 4, Rule 5, Rule 6, AC-3, AC-4, AC-9）**:
     - ブラウザ側で独自に raw capture を再解析せず、`GET /api/v1/captures/<id>` の `request`、`derived_views`、`replayability`、`replay_relations` をそのまま表示する読み取り専用ビューを実装した。
     - method、HTTP version、response status、capture status、routing（`route_id -> target (upstream_url)`）、timestamps/duration、wire URL、human-readable `decoded_path` vs wire `raw_path` / `raw_query`、body `sha256` / `captured_size / size` を明示表示。
     - Query / Headers / Cookies をインデックス付き（`#1, #2, ...`）順序保持テーブルとして描画し、duplicate key を map に潰さず順序通り表示。
     - Body derived view（整形 JSON、URL-encoded form テーブル、raw text / base64 / hex fallback、および `parse_errors` 発生時の fallback 通知）を実装。
     - Replayability ボックスに `replayable` 状態と理由（`truncated`、`metadata-only`、`capture-failed`、`missing_blob`、`websocket` 等）を表示し、non-replayable record では一覧・詳細双方の `Create Draft` アクションを `disabled` 化した。
     - Replay lineage ボックスで親 `source_capture_id` / `draft_id` へのジャンプボタン、および当該 capture から派生した child drafts / child replays へのナビゲーションボタンを実装した。
   - **Draft Editor・Normalized Wire Preview・Replay Confirmation・Export（Rule 3〜10, AC-3〜12, AC-14）**:
     - `POST /api/v1/captures/<id>/drafts`、`GET/PUT/PATCH/DELETE /api/v1/drafts/<draft_id>`、`GET /api/v1/drafts/<draft_id>/export`、`POST /api/v1/drafts/<draft_id>/replay` を利用する Draft Editor を実装した。
     - Method / Scheme / Authority / Human-Readable Decoded Path 入力、およびNormalized Wire Preview ボックス（送信されるリクエストライン、wire URL、percent-encoded `raw_path` / `raw_query`、再計算された `Content-Length`、除外された hop-by-hop headers `Connection` 等、side-effect warning badge）を分離表示した（Rule 4）。
     - Query / Headers / Cookies / URL-encoded Form それぞれに、順序と重複キーを保持したまま個別行の追加・値変更・削除・上下移動（`↑` / `↓`）ができる Ordered Pair Editor を実装した（Rule 3, AC-3, AC-5）。
     - Body Mode 切替（`json` / `urlencoded_form` / `raw_text` / `raw_base64` / `empty`）、検証・整形ボタン付き JSON Payload エディタ、および dot/index 指定（例: `user.profile.role`、`items.1.qty`）でサーバ側 `json_mutations` を適用できる Nested JSON Path Editor を実装した（AC-5）。
     - 未保存変更がある場合は `Unsaved Edits` バッジと Export パネルの stale 状態を表示し、Replay 実行や Export 更新時には自動的に最新編集をサーバへ保存してから実行することで、古い値と新しい値の混在を防止した（Rule 8）。
     - 非安全メソッド（`POST` / `PUT` / `PATCH` / `DELETE` 等）の Replay クリック時は、送信前にネイティブ `<dialog id="replay-confirm-dialog">` モーダルを開き、Method、正規化 Wire URL、Draft ID、および副作用警告文を明示して、`Confirm & Send Replay` が押された場合のみ送信し、`Cancel` 時は一切送信しない制御を実装した（Rule 7, AC-7）。
     - Replay 完了時は HTTP status、新 `result_capture_id`、lineage（`Source Capture -> Draft -> Replay Run -> New Capture`）、レスポンス JSON/body preview、および新 Capture Detail へワンクリックで遷移するボタンを表示した（Rule 9, AC-8）。
     - cURL / Local Edge cURL / Browser `fetch()` プレビューと Copy ボタンを実装し、Clipboard API が利用不能またはヘッドレス環境でタイムアウトした場合でもテキストボックスを即座に全選択（`Selected ...`）して手動コピー可能にした（Rule 10, AC-10）。
     - 期限切れ・削除済み Draft（`draft_not_found` / `draft_expired`）や JSON 構文エラー・構造化編集エラー時に明確なエラーバナーと回復アクション（`Recreate Draft from Source Capture` / `Reload Draft`）を表示する回復フローを実装した（AC-11）。

2. **Backend 補助拡張（`services/recorder/index_store.py`, `services/recorder/draft_replay.py`）**
   - `CaptureIndexStore.query_captures()` の各アイテムに `replayability`（`{replayable, reason, message}`）を付与し、一覧画面で `truncated` / `metadata-only` / `capture-failed` / `missing_blob` / `websocket` の理由を即座に表示・判定可能にした。

   - `DraftReplayManager.update_draft()` で `json_value` と `json_mutations` が同時に渡された場合にも `json_mutations` が確実に適用されるようにし、`normalized_preview` に `raw_path` と `raw_query` を追加した。

### 発見事項

- ヘッドレス Chrome 環境では `navigator.clipboard.writeText()` が権限プロンプト待ちで解決しない場合があるため、`copyOrSelectTextarea()` では即座に対象 `<textarea>` を `focus()` + `select()` して `Selected ...` 状態へ遷移させつつ、`navigator.clipboard.writeText()` に 150ms のタイムアウトを設けるプログレッシブエンハンスメントとすることで、通常ブラウザでのクリップボードコピーとヘッドレス/非権限環境での即座のテキスト選択フォールバック（Rule 10）を両立させた。
- `DraftReplayManager.update_draft()` において、`json_value`（テキストエリアからの JSON 全体送信）と `json_mutations`（Nested JSON Path Editor からのパス指定変更）を単一リクエストで同時送信した際にも `json_mutations` が後段で適用されるよう改善したことで、未保存のフォーム/ヘッダ/JSON 編集を失わずにネスト JSON パス操作をサーバ側で一括適用できるようになった。
