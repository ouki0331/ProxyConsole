## 機能ルール

1. Engine socketへの操作はread-only GETに限定する。
2. container IDはhost-wide inventoryから選択し、利用者入力の任意socket/pathへ展開しない。
3. `tail`は既定200、最大1000行とし、API response sizeにhard capを設ける。
4. Docker multiplexed streamは8-byte headerを検証してstdout/stderrを保持し、Podman/plain textも同じline contractへ正規化する。
5. timestampがある行はRFC3339として保持し、ない行は`null`とする。本文を翻訳・改変しない。
6. severityは`fatal|panic|critical|error`、`warn`、その他の順に派生分類し、raw textを保持する。
7. searchはcase-insensitive literal substringとし、regex実行やcode evaluationを行わない。
8. 一containerのlog取得失敗はworkspace全体やproxyを停止させず、source単位errorとして表示する。
9. pollingはLogs workspace表示中かつ利用者が有効にした場合だけ5秒以上の間隔で行い、hidden時に停止する。
10. filterと選択sourceはreload後に復元し、不正なcontainer IDはsource未選択へfallbackする。
11. `Alt+7`はinput/textarea/select/contenteditable/dialog編集中に発火しない。
12. raw log本文をGit、SQLite、capture storageへ新規永続化しない。

## API方針

- `GET /api/v1/runtime/logs?container_id=...&tail=...&since=...&severity=...&search=...`
- responseはprovider、container metadata、requested filter、lines、returned、truncated、refreshed_at、errorを返す。
- container IDがinventoryに存在しない場合は404、Engine unavailableは503、不正filterは400とする。

## 実装Agent記入欄

### 実装要約

1. host-wide inventoryでcontainer IDを照合してからDocker-compatible Engineの`GET /containers/{id}/logs`だけを呼ぶprovider-neutral logs serviceと`GET /api/v1/runtime/logs`を追加した。
2. tail既定200・最大1000、RFC3339 since、case-insensitive literal search、severity filter、2 MiB response hard capを実装した。unknown containerは404、不正filterは400、Engine unavailableは503で区別する。
3. Docker 8-byte multiplex frameを検証し、stdout/stderr、frameを跨ぐ行、RFC3339 timestampを保持した。Podman/plain textも同じ`timestamp/stream/severity/text` schemaへ正規化し、raw本文を永続化・翻訳・改変しない。
4. Runtime Projects inventoryをsource selectorに再利用し、system/external containerを同じLogs workspaceから選択できるようにした。loading、empty、partial inventory error、source error、unavailable、truncatedを別表示する。
5. project/container、severity、tail、since、literal search filter、manual refresh、表示中だけのoptional 5秒polling、reload persistence、不正source fallbackを追加した。
6. Logs navigationと`Alt+7`を追加し、既存input/textarea/select/contenteditable/dialog guard、日英表示、390px layoutを拡張した。
7. multiplex/plain decode、分割frame、byte cap、filter、Docker/Podman共通schema、HTTP 200/400/404/503 contractのunit/API testを追加し、browser E2EへAlt+7、filter/source reload persistence、hidden polling stop、input guard、390px検証を定義した。

### 発見事項

- byte capがmultiplex frame途中に到達した場合、完了frameだけをdecodeし、不完全frameをplain textとして誤表示しない処理が必要だった。
- Docker multiplex streamは一つのlog行が複数frameへ分割され得るため、stdout/stderr別のpending bufferで行を再構成した。
