## スコープ

含む:

- Docker-compatible Engine logs APIのDocker / Podman共通client
- stdout/stderr multiplex frameとplain text responseのdecode
- bounded tail、since、search、severity filter
- Runtime Projects inventoryを利用したproject/container source選択
- ProxyConsole edge/router/inspector/control-api log source
- Logs workspaceと`Alt+7`
- loading、empty、partial error、unavailable、refresh state
- manual refreshとbounded polling（画面表示中のみ）
- line timestamp、stream、severity、container metadata表示

含まない:

- 任意host file探索・読み取り

- container lifecycle操作
- log本文の変更・翻訳
- multi-user audit、secret自動redaction

## 機能ルール

1. Engine socketへの操作はread-only GETに限定する。
2. container IDはhost-wide inventoryから選択し、利用者入力の任意socket/pathへ展開しない。
3. `tail`は既定200、最大1000行とし、API response sizeにhard capを設ける。
4. Docker multiplexed streamは8-byte headerを検証してstdout/stderrを保持し、Podman/plain textも同じline contractへ正規化する。
5. timestampがある行はRFC3339として保持し、ない行は`null`とする。本文を翻訳・改変しない。
6. severityは`fatal|panic|critical|error`、`warn`、その他の順に派生分類し、raw textを保持する。
7. searchはcase-insensitive literal substringとし、regex実行やcode evaluationを行わない。
8. 一containerのlog取得失敗はworkspace全体やproxyを停止させず、source単位errorとして表示する。
9. pollingはLogs workspace表示中かつ利用者が有効にした場合だけ5秒以上の間隔で行い、hidden時に停止する。
10. filterと選択sourceはreload後に復元し、不正なcontainer IDはsource未選択へfallbackする。
11. `Alt+7`はinput/textarea/select/contenteditable/dialog編集中に発火しない。
12. raw log本文をGit、SQLite、capture storageへ新規永続化しない。

## API方針

- `GET /api/v1/runtime/logs?container_id=...&tail=...&since=...&severity=...&search=...`
- responseはprovider、container metadata、requested filter、lines、returned、truncated、refreshed_at、errorを返す。
- container IDがinventoryに存在しない場合は404、Engine unavailableは503、不正filterは400とする。

## 受入条件

1. multiplexed stdout/stderrとplain textのdecode unit testが成功する。
2. tail default/max、response byte cap、invalid filter、unknown containerを検証する。
3. Docker / Podman provider contractで同じlog line schemaを返す。
4. project/container source selectorからsystem/external containerを選択できる。
5. search、severity、tail、since filterを組み合わせ、raw textを改変せず結果を絞り込める。
6. unavailable/partial/empty/zero resultを区別して表示する。
7. manual refreshとoptional pollingがhidden workspaceで停止する。
8. `Alt+7`、reload persistence、input guard、390px viewportをbrowser E2Eで定義する。
9. P1〜P5、DEV-060、DEV-061のstatic/unit contractを回帰する。
10. phase完了時に利用可能runtimeでlocal CIを一回実行する。環境制約時はDeferred CIとして記録し、成功扱いにせず続行する。
11. runtime data、raw log、private key、screenshotをGitへ追加しない。
