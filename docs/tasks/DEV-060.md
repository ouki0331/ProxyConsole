# DEV-060 Japanese localization, overview dashboard, and workspace shortcuts

Status: In progress
Owner: implementer
Phase: P7
Product relation: CON-I18N-001, CON-DASH-001, CON-NAV-001

## 目的

既存 localhost Web console を英語 / 日本語で利用可能にし、初期表示をフォームのない統計 Overview に変更し、tab と keyboard shortcut で Routes & Docker、Requests & Replay、Modification Rules、Notifications へ即座に移動できるようにする。既存 proxy / capture / replay / rule / notification の business logic と API contract は変更しない。

## スコープ

含む:

- 英語 / 日本語 translation catalog と frontend localization helper
- browser locale による初期値、header language selector、選択の local persistence
- static copy と既知の dynamic status / validation / notification / ARIA copy の翻訳
- Overview を既定 workspace とする navigation 再構成
- フォームを持たない統計 / health dashboard
- Overview card から既存 workspace への deep navigation
- `Alt+1`〜`Alt+5` による workspace 切替と visible shortcut hint
- active workspace と language の reload persistence
- loading / empty / partial failure / stale / refresh state
- keyboard、focus、live region、狭幅 viewport を含む browser E2E

含まない:

- Runtime Projects / Logs workspace（DEV-061 / DEV-062）
- Docker log API、任意 host log file の読み取り
- 汎用 database client / SQL query UI
- 会社共有、login、SSO、RBAC、multi-user、public deployment
- proxy / capture / replay / rule / notification の backend business logic 変更
- machine translation、英語 / 日本語以外の翻訳
- user data、domain、container name、raw request、raw log、server error detail の翻訳

## UX / 機能ルール

1. Surface mode は `Operate` とし、既存 console の visual vocabulary を維持する。装飾目的の dashboard にせず、状態走査と workspace 移動を最優先する。
2. 初回 language は `navigator.languages` / `navigator.language` が `ja` 系なら日本語、それ以外は英語とする。手動選択は localStorage に保存し、browser locale より優先する。
3. 不明 translation key は英語へ fallback する。翻訳欠落で button、error、ARIA label を空にしない。
4. HTML `lang`、document title、navigation `aria-label`、dialog / field label、status live region を選択言語と同期する。
5. API 由来の既知 code / enum / status は表示ラベルを翻訳するが、domain、ID、container name、request body、raw log、診断 detail は原文を保持する。
6. Overview には create / edit / filter form を置かない。設定操作は既存 workspace だけに置く。
7. Overview は少なくとも次を表示する: proxy/control health、enabled/total routes と apply sync、Docker running/stopped/unavailable、直近24時間/全 capture、storage usage と soft/hard limit、open/unacknowledged incidents、SQLite health、last refresh。
8. 一つの API/card が失敗しても dashboard 全体を停止しない。該当 card だけ `Unavailable` / `利用不可` と retry/deep-link を表示する。実データの `0` を unavailable と混同しない。
9. Overview card は値に対応する既存 workspace へ移動できる。編集フォームを自動 submit / open しない。
10. shortcut は DEV-060 で `Alt+1` Overview、`Alt+2` Routes & Docker、`Alt+3` Requests & Replay、`Alt+4` Modification Rules、`Alt+5` Notifications とする。
11. input、textarea、select、contenteditable、dialog 内で利用者が編集している時は shortcut を発火しない。tab click は常に利用可能にする。
12. active tab は `aria-current` または同等状態、keyboard focus、selected styling を持つ。shortcut を tooltip または help text で発見可能にする。
13. 最後に選択した workspace と language を reload 後に復元する。ただし存在しない workspace ID は Overview へ fallback する。
14. 狭幅では navigation を折り返しまたは overflow-safe にし、統計カードと既存 workspace の主要操作を使用不能にしない。
15. この task で backend に新しい aggregate endpoint を追加する場合も、既存 endpoint semantics を変更せず、read-only summary に限定する。

### 実装要約

1. **英語 / 日本語 国際化 (i18n) 基盤 (`CON-I18N-001`)**:
   - `web/console/app.js` に `I18N_CATALOG`（英語 `en`・日本語 `ja`）を定義し、キーが見つからない場合の安全なフォールバックヘルパー `t(key, params)` を実装。

   - raw domain（`app-a.local.test` 等）、container name、route/request/rule ID、request body、server diagnostic detail は翻訳・改変せず原文を維持。
2. **フォームを持たない Overview ダッシュボード (`CON-DASH-001`)**:
   - `index.html` に `<div id="overview-workspace" class="console-workspace">` を追加し、初期表示ワークスペースとして設定。作成・編集・フィルタ等の入力フォームを一切持たない純粋な状態集約ダッシュボードとして構成。

### 実装範囲

1. `CONTAINER_RUNTIME=auto|docker|podman` を受け取る共通 runtime adapter を追加し、一回の実行中に runtime を混在させない。
2. scripts と integration tests の直接 `docker` / `docker compose` 呼び出し、および Python subprocess の固定 `"docker"` argv を adapter または明示環境値へ移す。
3. Docker socket と rootless/rootful Podman socket を host 上で解決し、control-api container 内では固定の Engine API socket path を使用する。host socket に対する `chmod 0666` は削除する。
4. Docker-compatible Engine API の既存 response contract を維持しながら provider (`docker|podman`) を status / discovery response へ追加する。
5. `make ci-local` を追加し、preflight、static/config check、全13 suite、cleanup、Git runtime artifact 検査を一回だけ実行する。
6. README と UI の必要箇所を provider-neutral な Container Engine 表現へ更新する。ただし既存 API field、route target ID、保存済みデータを破壊的 rename しない。

### 受入条件

1. Podman を利用できるローカル環境では `CONTAINER_RUNTIME=podman make ci-local` により全13 suite を実行する。権限、runtime、socket、Compose provider の制約で実行不能な場合はコマンドとエラーを記録して `Deferred CI` とし、実装作業を停止しない。
2. Docker を利用できるローカル環境では `CONTAINER_RUNTIME=docker make ci-local` により同じ全13 suite を実行する。実行不能な場合は同様に `Deferred CI` とし、後日補完する。
3. runtime が存在しない、Compose provider がない、Engine socket がない場合は preflight が非0終了し、利用可能な修正手順を表示する。
4. `auto` は Podman / Docker の利用可否を検出して一つだけ選び、選択結果を表示する。明示指定 runtime が利用不能な場合は他方へ fallback しない。
5. test failure 時も cleanup を実行し、test container / network / volume を残さない。既存 runtime resource は削除しない。
6. socket permission を変更せず、read-only Engine API discovery が Docker / Podman の双方で動く。
7. `node --check`、`python3 -m py_compile`、`bash -n` が成功する。
8. 実行 command、runtime/provider version、結果要約、未実行側、生成物、未検証事項をこの文書に追記する。Deferred CI は成功と表現せず、`docs/development/STATUS.md` の検証 backlog に残す。
