# DEV-022 Web route / Docker 管理 console

Status: In progress
Owner: implementer
Phase: P3
Product relation: ROUTE-HOST-001, ROUTE-HOST-002, ROUTE-HOST-003, ROUTE-HOST-004, ROUTE-DOCKER-001, ROUTE-DOCKER-002

## 目的

localhost で開く管理画面から、route の一覧・作成・編集・複製・有効化・無効化・削除と、Docker target または手動 host/port の選択を完結できる最小 Web console を実装し、P3 のユーザー可視フローを完成させる。

## スコープ

含む:

- localhost から利用できる Web console entry point
- route 一覧と enabled/disabled、domain、upstream、target state、apply status の表示
- route create/edit/delete
- route copy（新 domain 必須）
- enable/disable
- Docker container/port の refresh、状態表示、target 選択
- Docker target と手動 scheme/host/port の切替
- 同一 target を複数 route から選択可能
- apply/validation/reload/rollback failure の画面内表示
- loading、空一覧、Docker unavailable、入力 validation、操作成功/失敗 state
- local API を利用した UI。Docker socket や DB/filesystem を browser から直接操作しない
- 自動 integration test と browser-level smoke test

含まない:

- 認証、ユーザー/権限管理
- 公開 internet 向け管理画面
- capture viewer、request editor、replay、cURL/fetch 出力（P4）
- notification / WebSocket event feed（P5）
- Docker container の作成、削除、start/stop 操作
- security hardening、機密情報 filter、Docker Socket 最小権限化（P6）

## UX / 機能ルール

1. 最初の画面で route 一覧と現在の routing/apply 状態を確認できる。
2. route 操作は既存 DEV-020 API を利用し、UI 内に別の route business logic を複製しない。
3. Docker target 選択は DEV-021 discovery API を利用し、container 名、状態、network、port を識別できる。
4. stopped target は状態を表示し、新規 live target として誤選択させない。
5. Docker unavailable 時も manual target 入力と既存 route 管理を利用できる。
6. copy は新 domain 入力を必須とし、元 route を変更しない。
7. destructive delete は対象 domain を明示した確認を行う。
8. API error、validation error、apply/rollback error を成功表示にしない。利用者が次に修正すべき field または再試行操作を示す。
9. 操作後は server state を再取得し、楽観表示だけで完了扱いにしない。
10. UI は localhost のみを既定公開範囲とし、認証の追加を現在の blocker にしない。

## 受入条件

1. DEV-001〜DEV-021 の全 test が引き続き成功する。
2. 一つの documented command で console を起動し、localhost URL を開ける。
3. route 一覧に domain、enabled、upstream、Docker/manual 種別、target state、apply status が表示される。
4. manual scheme/host/port で route を作成・編集し、実際の HTTPS request が対象へ到達する。
5. Docker container/port を画面で refresh・選択して route を作成し、実際の request が選択 port へ到達する。
6. route copy で新 domain を作成し、元 route と同一 target へ到達する。
7. enable/disable が live routing に反映され、画面を再読込しても server state と一致する。
8. delete 確認後に route が削除され、対象 domain が 404 になる。
9. duplicate domain、無効 port、空 host、stopped target を UI が error として表示し、既存 route を壊さない。
10. Docker unavailable を画面に表示しつつ、manual target route の作成・疎通が成功する。
11. Nginx validation/reload failure の apply status と error が画面に表示され、旧 route の応答が継続する。
12. browser-level test または再現可能な browser smoke で、一覧、create、copy、disable/enable、Docker selection、manual fallback、error state を検証できる。
13. console の操作が capture/index/retention chain を迂回しない。

## 実装上の既定

- `web/console` を UI source の境界とする。
- build tool/framework は、現在の local console に必要な最小構成を選ぶ。静的 HTML/CSS/ES modules で十分なら新しい package manager 依存を追加しない。
- console の配信は既存 control API か専用 local-only service のどちらでもよいが、起動 command と URL を固定し、自動 test で検証する。
- API response を UI 独自の永続 state として複製しない。
- desktop を主対象としつつ、狭い画面でも主要操作が失われない layout とする。
- security hardening を理由に task を停止しない。

## G3 判定

DEV-022 の独立 review で受入条件 1〜13 が合格した場合、DEV-020〜DEV-022 を合わせて G3 passed とする。不正 route が既存 route を停止する、Docker target を UI から選択できない、または manual fallback が使えない場合は G3 を通過させない。
