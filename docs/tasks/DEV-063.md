# DEV-063 ローカルCI実行環境とPodman Compose互換性

Status: In progress
Owner: orchestrator
Phase: P7 verification backlog
Product relation: local CI / runtime compatibility

## 目的

GitHub Actionsを使用せず、既存の`make ci-local`をPodman環境で実行可能にし、不要ブランチの有無を安全に確認する。

## 必須コンテキスト

- `/AGENTS.md`
- `/docs/development/STATUS.md`
- `/docs/development/PLAN.md`のlocal CI方針
- この文書

## スコープ

含む:

- ローカルCI依存関係の確認とローカル環境への導入
- Podman ComposeとDocker Composeの引数互換修正
- runtime shimの回帰テスト
- `CONTAINER_RUNTIME=podman make ci-local`の実行
- ローカル／リモートの完全マージ済み不要ブランチ確認

含まない:

- GitHub Actions workflowの追加または実行
- 未マージブランチの削除
- Docker未導入環境でのDocker local CI成功扱い
- 製品機能の追加

## 受入条件

1. GitHub Actionsを追加・実行しない。
2. Podman Compose 1.5.0でDocker Compose互換のbuild commandを実行できる。
3. Docker providerでは既存引数を変更しない。
4. runtime unit testとPodman local CIの実行結果を記録する。
5. `main`以外のブランチは、完全マージ済みと確認できたものだけを削除する。
6. runtime data、証明書秘密鍵、個人情報をGitへ追加しない。

## 可行性確認

- Podman 5.7.0、podman-compose 1.5.0、rootless socketは利用可能。
- `make`とNode.jsは当初未導入だったが、ローカルCI依存関係として導入可能。
- `.github/workflows`は存在せず、hosted CIを追加しない既存方針と一致する。
- ローカル／リモートブランチは調査時点で`main`のみで、削除対象はない。
