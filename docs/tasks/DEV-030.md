# DEV-030 Request draft / replay / export core

Status: Done
Owner: none
Phase: P4
Product relation: CAPTURE-DETAIL-001, REPLAY-EDIT-001, REPLAY-SEND-001, REPLAY-EXPORT-001

## 目的

保存済みの replayable request から編集可能な draft を作成し、query、headers、cookies、JSON、URL-encoded form を人間可読の形で変更して安全に再送し、同じ内容を cURL / fetch として出力できる local API / CLI core を実装する。後続の Web editor が raw capture を再解釈せず、この core をそのまま利用できる契約を固定する。

## スコープ

含む:

- replayable capture から request draft を生成
- method、scheme、authority/host、path の表示と編集
- 重複・順序を保持する query/header editor model
- Cookie header の解析 view と再構築
- JSON body の構造化表示・編集・再 encode
- `application/x-www-form-urlencoded` の重複 key を保持する表示・編集・再 encode
- raw/text body fallback と content type/body metadata 表示
- URL percent-decoding した人間可読 view と送信時の正しい再 encode
- replay 前の request normalization
- hop-by-hop header 除外と `Content-Length` 再計算
- replayable/non-replayable 判定と明示 error
- cURL と browser fetch JavaScript export
- POST/PUT/PATCH/DELETE の副作用 warning metadata
- local HTTP API と CLI
- draft/replay/export の自動 integration test

含まない:

- Web request editor UI（DEV-031）
- multipart file の任意編集（初期 core では metadata/raw fallback とし、既存 exact replay を壊さない）
- WebSocket frame replay/edit
- gRPC message replay/edit
- live interception / request pause
- 自動 request modification rule（P5）
- security hardening、認証、機密値 filter（P6）

## 機能ルール

1. draft は元 capture を変更せず、新しい一時/永続 draft ID を持つ。
2. query と headers は list-of-pairs として重複・順序を保持する。
3. percent-decoded view と wire representation を区別し、decode/encode の往復で意味を変えない。
4. JSON と URL-encoded form は構造化 edit を提供し、解析不能時は raw fallback と明示 error を返す。
5. replay 時は `Connection` 等の hop-by-hop header を送らず、body 変更後の `Content-Length` を再計算する。
6. `complete` かつ必要 body blob が存在する record だけを replayable とし、truncated/metadata-only/capture-failed/missing blob は理由付きで拒否する。
7. GET/HEAD 以外、特に POST/PUT/PATCH/DELETE は副作用 warning を返すが、local user の明示 replay 操作自体は阻止しない。
8. export は現在の draft 内容を反映し、元 capture の古い値を混在させない。
9. cURL export は shell quoting、fetch export は JavaScript string/body encoding を再現可能にする。
10. replay request 自体も通常の inspector/capture/index/retention chain を通過し、新しい capture として識別できる。

## 受入条件

1. DEV-001〜DEV-022 の全 test が引き続き成功する。
2. replayable capture から draft を作成し、元 capture が不変である。
3. duplicate query/header の順序を保持したまま一項目を追加・変更・削除できる。
4. percent-encoded Unicode、space、reserved character を人間可読に編集し、送信時に意味を保って再 encode できる。
5. JSON の nested field と URL-encoded form の重複 key を編集して target が期待値を受信する。
6. cookie view の追加・変更・削除が送信 Cookie header に反映される。
7. body 変更後に hop-by-hop header が除外され、Content-Length が正しく再構築される。
8. GET/POST/PUT/PATCH/DELETE の replay が指定 route/target へ到達し、非安全 method に warning metadata がある。
9. truncated、metadata-only、capture-failed、missing blob の replay が理由付きで拒否され、target に到達しない。
10. draft から生成した cURL と fetch が syntactically valid で、少なくとも代表的な JSON/form request について同じ target-observable semantics を再現する。
11. replay 後に新 capture が検索可能となり、元 capture ID/draft ID/replay relation を追跡できる。
12. service/container restart 後の draft persistence 方針が実装と文書で一致する。永続化する場合は read-back、しない場合は明示 expiry/not-found を検証する。
13. 一つの自動 test command で draft、editing、replay、export、failure cases を再現できる。

## 実装上の既定

- capture raw bytes と derived view の境界を維持し、draft edit で保存済み capture/blob を上書きしない。
- DEV-002 の semantic replay と DEV-010 detail/index API を再利用し、別の replay engine を重複実装しない。
- editor model は後続 Web UI から扱いやすい JSON contract としつつ、wire fidelity を優先する。
- draft persistence は SQLite を既定とし、明示 delete/expiry を設ける。別方式を選ぶ場合は restart behavior と理由を task 文書に記録する。
- export string を実行する機能は不要で、生成結果と独立した test execution で再現性を検証する。
- security hardening を理由に task を停止しない。

## 失敗時の扱い

- draft edit が元 capture/blob を変更する場合は `Blocked` とする。
- duplicate query/header または body encoding の意味を保持できない場合は `Ready for review` にしない。
- non-replayable record が target へ送信される場合は即時停止し、既存 capture data を保持して修正する。
- security hardening を理由に task を停止しない。

## 実装 Agent 記入欄

### 実装要約

- **SQLite スキーマ拡張（`migrations/005_request_drafts.sql` / `INDEX_SCHEMA_VERSION = 5`）**:
  - `request_drafts` テーブル（`draft_id`, `source_capture_id`, `name`, `method`, `scheme`, `authority`, `host`, `raw_path`, `decoded_path`, `raw_query`, `query_params_json`, `headers_json`, `cookies_json`, `body_mode`, `content_type`, `body_bytes`, `body_json_text`, `body_form_json`, `parse_errors_json`, `notes`, `expires_at`, `created_at`, `updated_at`）および `replay_runs` テーブル（`replay_id`, `draft_id`, `source_capture_id`, `result_capture_id`, `method`, `scheme`, `authority`, `raw_target`, `body_size`, `body_sha256`, `response_status`, `side_effect_warning_json`, `replayed_at`）を追加した。
  - `index_store.py` にて `_connect()` を `@contextlib.contextmanager` 化してトランザクション終了時に必ず `conn.close()` を実行するように改善し、`rebuild_index()` では健全な DB に対する in-place トランザクション再構築と破損時のフォールバック双方で `request_drafts` / `replay_runs` を保持するようにした。
- **Request Draft / Replay / Export Core（`services/recorder/draft_replay.py`）**:
  - **Replayability 厳密検証**: `capture_status == "complete"`、`replayable == true`、`is_websocket == false`、および `blob_ref` の実ファイル存在・サイズ・SHA-256 一致を検証し、`truncated`、`metadata-only`、`capture-failed`、`missing_blob`、`incomplete_blob`、`websocket` を理由コード付き `NonReplayableCaptureError`（HTTP 400 `non_replayable_capture`）で拒否し target への送信を防止した。
  - **不変性と永続 Draft 管理**: 元 capture の JSON / blob ファイルを一切変更せず、独立した `draft_id` と任意 TTL（`ttl_seconds` / `expires_at`）を持つ SQLite 永続 draft として作成・取得・一覧・更新・削除・期限切れ自動除外（prune）を実装した。
  - **順序・重複保持エディタモデルと Percent-Encoding 往復**:
    - `query_params`、`headers`、`cookies`、`form_fields` をすべて順序付き list-of-pairs `[[key, value], ...]` として保持し、全体の置換だけでなく `query_mutations`、`header_mutations`、`cookie_mutations`、`form_mutations` による出現位置指定（`occurrence`）付きの `add` / `set` / `remove` 操作を実装した。
    - `decoded_path`（各 path segment を percent-decode した人間可読表現）と `raw_path`（wire representation）の分離および往復変換、`query_params` の `quote(safe="")` による予約文字・空白・Unicode の厳密な再 encode を実装した。
  - **構造化 Body 編集と Raw Fallback**:
    - JSON body（`body_mode="json"`）に対して `json_value` / `json_text` の全体更新およびドット/インデックス表記対応の `json_mutations`（`set` / `remove`）による nested field 編集と再 encode を実装した。
    - `application/x-www-form-urlencoded` body（`body_mode="urlencoded_form"`）に対して重複 key と順序を保持した `form_fields` / `form_mutations` 編集と再 encode を実装した。
    - 不正な JSON / form を持つ capture からの draft 生成時は `parse_errors` を記録して `raw_text` / `raw_base64` へ安全にフォールバックし、その状態で構造化編集が要求された場合は明示的な `DraftValidationError`（HTTP 400 `structured_body_unavailable`）を返し、`raw_text` / `raw_base64` での編集・再送を可能にした。
  - **Request Normalization と Replay 実行**:
    - Replay / Export 前に `Connection`（および `Connection` ヘッダ内で指定されたカスタム hop-by-hop ヘッダ名）、`Keep-Alive`、`Transfer-Encoding`、`Te`、`Trailer`、`Upgrade`、`Proxy-Connection`、`Proxy-Authenticate`、`Proxy-Authorization`、ならびに既存の `Host` / `Content-Length` / `X-Forwarded-*` を除外し、`excluded_hop_by_hop_headers` として可視化した上で、編集後の `Cookie` ヘッダ再構築と body バイト長に基づく `Content-Length` 再計算を行う。
    - `GET` / `HEAD` / `OPTIONS` / `TRACE` 以外のメソッド（`POST`, `PUT`, `PATCH`, `DELETE` 等）には `side_effect_warning` メタデータ（`has_side_effect_warning: true`, `warning_code: "non_idempotent_or_mutating_method"`）を付与しつつ、local user の明示的な replay 操作を実行する。
    - Replay 送信は HTTPS edge を通過して通常の `inspector -> router -> target` チェーンを経由し、生成された新 capture の `capture_id` を `replay_runs` に紐付けて記録する。`GET /api/v1/captures` の `--source-capture-id` / `--draft-id` フィルタおよび `GET /api/v1/captures/<id>` の `replay_relations` で親子関係を双方向に追跡可能とした。
  - **cURL / Browser fetch Exporters**:
    - 現在の正規化済み draft 内容のみから POSIX shell 安全な `curl` / `curl_local_edge` コマンド文字列と、JavaScript `fetch(url, init)` スニペットおよび構造化 `fetch_request` オブジェクトを生成する exporter を実装した。
- **HTTP API / CLI 拡張（`services/recorder/api_server.py`, `services/recorder/capture_cli.py`, `scripts/capture-ctl.sh`）**:
  - HTTP API: `GET /api/v1/captures/<id>/replayability`, `POST /api/v1/captures/<id>/replay`, `POST /api/v1/captures/<id>/drafts`, `GET/POST /api/v1/drafts`, `GET/PUT/PATCH/DELETE /api/v1/drafts/<draft_id>`, `GET/POST /api/v1/drafts/<draft_id>/export`, `POST /api/v1/drafts/<draft_id>/replay`, `POST /api/v1/drafts/prune` を追加。
  - CLI (`capture-ctl.sh`): `replayability`, `draft-create`, `draft-list`, `draft-get`, `draft-update`, `draft-delete`, `draft-export`, `draft-replay` サブコマンド、および `list` サブコマンドへの `--source-capture-id` / `--draft-id` オプションを追加。

### 発見事項

- `deploy/nginx/edge/default.conf` は upstream（`inspector`）へ転送する際に `proxy_set_header Connection "";` を設定するため、外部クライアントが送信した `Connection` ヘッダは初期 capture には残らない。これに対し、初期 capture に含まれる `Host` / `Content-Length` / `X-Forwarded-*` に加え、draft 編集で明示追加された `Connection: keep-alive, X-Custom-Hop` や `Keep-Alive`、`Transfer-Encoding` 等も含めて `_normalize_row()` で一貫して hop-by-hop 除外・記録するように実装し統合テストで検証した。
- Python 標準ライブラリの `sqlite3.Connection` は `with conn:` ブロック終了時にトランザクションの commit/rollback のみを行い `conn.close()` を呼ばないため、プロセス内で未 GC の接続が残っている間に別プロセスが DB ファイルを unlink すると SQLite の POSIX VFS が `SQLITE_READONLY_DBMOVED`（`attempt to write a readonly database`）を返す場合があることを確認した。`CaptureIndexStore._connect()` を `@contextlib.contextmanager` 化して `finally: conn.close()` を保証し、`rebuild_index()` も健全な DB に対してはファイルを unlink せず in-place トランザクションで再構築するようにしたことで、並行アクセス下でも安定して動作することを確認した。
